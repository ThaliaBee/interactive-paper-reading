# 计算机科学论文阅读笔记

以论文原文为依据维护可持续增补的学习笔记，区分原文事实、中文解释、外部补充和用户自己的思考。

## 开始任务

1. 从用户指定的论文路径、附件、链接或当前上下文确定论文及所需操作。论文有歧义或无法访问时说明缺少什么，不根据标题编造内容。
2. 若目标笔记已存在，先读取并定位相关章节；用户指定笔记路径优先。默认将笔记写入**用户当前项目**的 `notes/`，而非 skill 安装目录。
3. 新建笔记时读取 [references/note-format.md](references/note-format.md)；维护既有笔记时读取其中对应条目格式。
4. 按下表选择操作，只读取需要的操作说明。用户只说“做笔记”而未指定模式时，默认生成空白笔记，并在完成后说明采用了该模式。

| 用户意图 | 执行方式 |
| --- | --- |
| 生成空白笔记 | 填写已确认基本信息，保留其他栏目为空 |
| 添加指定术语、生词、写作词汇、问题或想法 | 按对应格式增补指定条目 |
| 自动添加术语 | 完整提取论文命名并定义或解释的术语 |
| 添加指定辅助理解信息 | 按机构/Venue、相关论文、领域术语或其他分类增补 |
| 自动添加相关论文 | 收集并核验与本文问题直接相关的工作 |
| 生成自动笔记 | 依次完成空白笔记、自动术语、自动相关论文 |

- 基础创建、定向追加、自动术语、自动笔记：读取 [references/operations.md](references/operations.md)。
- 辅助背景、机构/Venue 或相关论文：读取 [references/background-research.md](references/background-research.md)。自动笔记也需要此参考。

## 证据与范围

- 完整阅读与所选操作有关的内容。概述挑战、方法、实验时覆盖正文及关键图表；自动术语和相关论文需要系统通读，不能只看标题或摘要。
- 定义优先使用论文中的必要短引，并记录章节或页码。找不到明确定义时写“论文未给出明确的定义”；解释性原文可注明其性质，不包装成正式定义。受引用限制时使用明确标注的忠实转述并保留定位。
- 术语、生词和写作表达保留原文语言；中文解释结合本文语境，先给译名或直观含义，再解释其作用、例子、前提或与主线的关系。
- 原文事实、个人理解和外部信息分别标明。外部信息给出可访问链接或完整书目信息；仅凭已有知识解释基础概念时标注“模型已有知识，未额外检索”。
- 用户疑问记录为 `论文内已回答`、`论文内部分回答`、`论文未回答` 或 `需外部求证`，附论文证据。不要把模型的解释写成用户已表达的观点，也不要代填 `# 我的想法`。
- 不猜测作者、机构、Venue、日期、CCF 等级、IF 或实验结论。发表时间优先 `YYYY/MM`；只能确认年份时写 `YYYY（月份未确认）`。区分预印本发布与会议/期刊发表，不以投稿日期代替发表时间。
- 默认只做用户指定的笔记操作。未经要求不追加生词、写作词汇、背景或其他术语；“自动笔记”的授权范围以对应操作说明为准。
- 自动收录默认完整覆盖，不预设数量上限。若用户明确限定章节、数量或范围，以当次要求为准，并说明尚未完成全篇收录。
- 无法读取全文、辨认图表、联网或核验部分资料时，先完成有证据支持的部分，报告具体缺口；不要把“未能核验”写成“原文没有”或“目录未收录”，也不要宣称完整完成。

## 文件命名与修改

- 默认文件名为 `[核心模型简称]_[论文标题].md`；没有明确简称时仅用论文标题，不发明简称。简称已是标题开头时不重复添加。
- 将空格、冒号和文件系统非法字符替换为 `_`，避免文件名末尾的空格或句点。例如 `Cordis_A_Programming_Paradigm_for_Spatiotemporal_Composability.md`。
- 新建文件前检查是否已有同一论文的笔记。已有内容以增量维护为主；不要因再次请求生成笔记而覆盖用户记录。
- 添加指定条目时，只在对应章节末尾追加，不改写其他条目。遇到已有同名内容时避免重复；需要补充或纠正时，按用户意图更新对应条目。
- 旧笔记缺少本次需要的章节时，只补该章节，保持既有标题层级与语言风格；不要顺带重排整份笔记。
- 保持 Markdown 表格可读；单元格内的 `|` 转义为 `\|`，必要的换行用 `<br>`，不因原文公式破坏表格。

## 完成回复

简短报告写入的文件路径、所执行的操作和实际新增或更新的条目；说明未确认的元数据、访问限制和剩余覆盖范围。没有文件写入能力时交付可复制的 Markdown，并明确未保存文件。
